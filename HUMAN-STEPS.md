# Human steps for the v0.4.0 release

Updated November 16, 2026. Use the existing production project and stay on the free plans. Enter secrets and the private inbox address only in the relevant provider dashboard.

1. **Verify Formspree and open Contact (10–15 minutes).** Open the delivered Formspree verification email for `support@bluelinelease.com` and choose **Verify email**. In Formspree → the existing contact form → **Workflow → Email**, change the recipient to `support@bluelinelease.com`. Send a synthetic contact and feedback submission from a local or preview app using that form. Check delivery, the subject `[Blueline Lease] Website Contact`, and the contact reply address. In Vercel → **Settings → Environment Variables**, remove the obsolete `FORMSPREE_FORM_ID` entry when ready to switch. After the new test arrives, set the verified `FORMSPREE_FORM_ID` and `FORMSPREE_SUPPORT_VERIFIED=true` for Production, redeploy, and repeat both tests. Until then the site directs users to the verified support inbox.
2. **Open Resend and verify the sending domain (10–20 minutes, plus DNS propagation).** Sign in or create an eligible Free account at [Resend Domains](https://resend.com/domains). Accept any account terms yourself. Choose **Add Domain → bluelinelease.com**, choose the US sending region if offered, and copy the domain's displayed DNS values into Cloudflare → **DNS → Records**. Keep DNS-only mode and TTL Auto. Return to Resend and choose **Verify DNS Records**. Leave Resend Receiving off. This unblocks branded outbound email.

   | Type | Name | Value | TTL | Purpose |
   | --- | --- | --- | --- | --- |
   | CNAME | `@` | `2c999c955c014cdf.vercel-dns-017.com` | Auto | Vercel apex, already saved DNS-only |
   | CNAME | `www` | `2c999c955c014cdf.vercel-dns-017.com` | Auto | Vercel secondary host, already saved DNS-only |
   | MX | `@` | `route1.mx.cloudflare.net` (67), `route2.mx.cloudflare.net` (58), `route3.mx.cloudflare.net` (45) | Auto | Cloudflare inbound, already saved |
   | TXT | `@` | `v=spf1 include:_spf.mx.cloudflare.net ~all` | Auto | Cloudflare root SPF, already saved |
   | TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:support@bluelinelease.com` | Auto | DMARC monitoring, already saved |
   | TXT | Resend DKIM selector, usually `resend._domainkey` | Copy the exact Resend public record | Auto | Resend signing |
   | MX | Resend return path, usually `send` | Copy the exact Resend MX host and priority | Auto | Return-path bounces |
   | TXT | Same Resend return-path hostname | Copy the exact Resend SPF record | Auto | Return-path SPF |

   Resend normally uses SPF on its return-path subdomain while Cloudflare uses SPF on the apex. Keep one SPF TXT record per hostname. If Resend actually asks for an apex SPF mechanism, merge it into the existing apex entry rather than adding a second record. Verify with `dig MX bluelinelease.com`, `dig TXT bluelinelease.com`, `dig TXT _dmarc.bluelinelease.com` and the corresponding Resend selectors. [Resend domain setup](https://resend.com/docs/dashboard/domains/introduction) · [Cloudflare mail DNS](https://developers.cloudflare.com/email-service/configuration/domains/)
3. **Install branded signup email (15–25 minutes).** Create a domain-scoped Sending Access key in Resend → **API Keys** for Supabase SMTP. Paste it only into Supabase → project `blueline` → **Authentication → Emails → SMTP Settings**. Enable custom SMTP and set sender `no-reply@bluelinelease.com`, name `Blueline Lease`, host `smtp.resend.com`, port `587`, user `resend`, and the key as password. Keep **Confirm email** on. Install the four templates using the [signup runbook](docs/handoff/signup-confirmation.md). Use `support@bluelinelease.com` for Reply-To if the verified provider configuration supports it. Hosted Supabase SMTP does not expose a direct Reply-To field, so verify the received headers and use the support address in the email body. Test code, confirmation link, reset and email change with synthetic, controlled non-team addresses. Record inbox versus spam and landing host. In Vercel set `AUTH_EMAIL_DELIVERY_VERIFIED=true` for Production and redeploy only after the sender passes. [Resend SMTP](https://resend.com/docs/send-with-smtp) · [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp)
4. **Organize email in Gmail (10–15 minutes).** In **Settings → See all settings → Labels**, create `Blueline Lease` and the nested labels `Blueline Lease/Support` and `Blueline Lease/Direct`. A connector label check did not identify a matching label for the existing forwarding domain. In **Filters and Blocked Addresses → Create a new filter**, add these rules:
   - **To** `support@bluelinelease.com`: apply Support, never send to spam, mark important, and apply to matching conversations.
   - **To** `alexismendez@bluelinelease.com`: apply Direct, never send to spam, and apply to matching conversations.
   - **Has the words** `deliveredto:bluelinelease.com`: apply the parent label and never send to spam. Test with a catch-all message. If the forwarder retains only the final mailbox in `Delivered-To`, use a domain-address `to:` match or the verified original-recipient header behavior as an additional filter.
5. **Add Gmail send-as (10–15 minutes).** Create a separate domain-scoped Resend Sending Access key for manual replies. In Gmail **Settings → Accounts and Import → Send mail as → Add another email address**, add each public-domain alias using `smtp.resend.com`, port `587`, TLS, username `resend`, and that key. Open the two confirmation emails delivered through forwarding and confirm them. Select **Reply from the same address the message was sent to**. Verify a reply to an outside account shows the intended From address. [Gmail send-as](https://support.google.com/mail/answer/22370)
6. **Rehearse a privacy request (15–25 minutes).** After SMTP works, create a synthetic account, send a synthetic support request from its account address, and follow the [deletion procedure](docs/legal/privacy-deletion-procedure.md). Verify which synthetic account, review, red-line, form, and mailbox records are removed. Record the result using the synthetic request ID. Keep real user records untouched.
7. **Review vendor agreements (20–30 minutes).** Open the [vendor agreement list](docs/legal/vendor-dpas.md). For each vendor, check which terms apply to the current account, use its Legal or Terms page to see the applicable agreement, and accept only if authorized and necessary. Save the revision and date privately. Confirm Formspree handles deletion of older submissions and OpenRouter's terms cover the deployed Fireworks route. Vercel's listed DPA is scoped to Pro and Enterprise. Stay on Hobby and record coverage as unresolved unless Vercel confirms otherwise.
8. **Approve the Rhode Island sources (20–30 minutes).** Compare the compiled sections and current public-law index, then record the reviewer, date, expiry, and exact fingerprints in the [source register](docs/legal/rhode-island-sources.json). Test from a hosted deployment while keeping the public page off. When all checks pass, set `RHODE_ISLAND_RESOURCES_ENABLED=true` in Production, redeploy and check the page. [Pilot instructions](docs/legal/rhode-island-pilot.md)
9. **Optional business and name steps.** Review [Rhode Island's LLC and trade-name options](https://www.sos.ri.gov/divisions/business-services/ri-business/start-your-rhode-island-business) and [USPTO trademark filing](https://www.uspto.gov/trademarks/basics/trademark-process). Those filings may cost money. For a no-cost review if eligible, use the [counsel packet](docs/legal/counsel-packet.md) and the [Roger Williams Business Start-up Clinic intake](https://law.rwu.edu/sites/law/files/downloads/academics/docs/bsu-clinic-intake-form2017.pdf).
